# 报告与证据格式（现行版）

> **总纲**：本页全部条文受 **SKILL H-21 零伪造总纲**（2026-10-15 用户令「任何东西都不允许伪造」）压顶——任何交付物元素必须真实发生且与证据本体一比一对得上；证据不够就如实写不够，如实呈现缺陷永远合规，把缺陷包装成完整才违规。任何条文与总纲冲突时以总纲为准。
>
> 谁读：分身（排版）、曹操（收卷）、采证角色（拍照/录屏前）。
> 何时读：步 11 出卷前、任何证据图/录屏拍摄前。
> 上游：SKILL 步 11 与「按需读」；外部权威：`~/.zcode/rules/vuln-report-format.md`（改号全套细则，两层都过才算出卷）。
> 本页只写现行口径；沿革查 CHANGELOG，判例库未随仓库发布。

## 一、文档版式（RF-DOC）

| ID | 规则 |
|---|---|
| RF-DOC-01 | 每步双灰底普适：复现每步 = 一两句说明 → 单独一行「请求包：」灰底整包 → 单独一行「响应包：」灰底真实响应整包；步与步之间全角＃；请求响应拆两块，禁塞同一代码框。请求包保持原始 HTTP dump 形态：Host 头紧跟请求行（整包缺 Host 由闸拦，这里管排版位置） |
| RF-DOC-02 | 「源码依据」标准块（白盒/反编译场，修复建议后＃接入）：逐出处「出处：file:line 或 jar+类」+ 真实源码段（Consolas 9pt，不格式化不补行号），问题点 `// 问题：` 行内标注；反编译件注明（javap 等）；黑盒场省略。行内注释代码分析保留（`// 无校验menuIds` 风格逐行点缺的闸）；服务端 Debug 日志不要求 |
| RF-DOC-03 | 字体字号：标题 16pt / 正文 12pt / 包与源码 Consolas 9pt / 灰底 F2F2F2。无 PPT 封面 |
| RF-DOC-04 | 操作指引：每步一两句人话告诉审核怎么做（哪个页面点什么、哪个框输什么、执行后去哪看什么），照做能一步不卡重放；篇幅不设上限，讲明白优先。**PoC 禁偷工（PoC 增量铁律，RF-PKG-05）**：复现步骤必须写手动全链（登录→到功能→触发→看到效果），禁「运行 poc.py 即可复现」把步骤折叠进脚本——PoC 是交付包里的增量复核件（RF-PKG-04/05），不是步骤的替代 |
| RF-DOC-05 | 真实命令原文照贴：凡输入过的命令（环境准备/登录/跑脚本/验证）cmd 原文连提示符带输出，按实际时间顺序排（先敲的在前，命令与请求包交错均可）；每条旁注一句「这条干什么用」（灰底小字，原文不动） |
| RF-DOC-06 | 脚本全文进 DOCX：「附：脚本全文」段（Consolas 9pt 灰底），py/js/bat/sql 探针一律全文上卷，无长度豁免；审核不解压也能逐行看懂 |
| RF-DOC-07 | 报告副本：DOCX 之外同目录再存同名 PDF 副本（LibreOffice）。DOCX 正本独立在档永不进 zip；PDF 原档独立在档，另复制一份进交付包 |
| RF-DOC-08 | 8 块正文一律不许脱敏：token/Cookie/Bearer/口令/密文/手机号/姓名写实测实值；禁 `<REDACTED>`、`credential_ref` 占位、只留前几位。请求响应必须是本场真实落盘原件（UA/鉴权头/Content-Length/body 序列化与实测一致——本场用 urllib 就是 `Python-urllib/3.12` + `Authorization: Bearer`，中文 `json.dumps` 默认 `\uXXXX`；CHAIN 没落该步回包时只许同账号同 host 同 UA 实测 dump 补全并写明出处） |
| RF-DOC-09 | 卷内禁出现：内部角色名（曹操/司马懿/于禁等）、内部账指针（CHAIN-编号、`02-cao-cao` 等目录名、verification.json、观察册）、`run_id`/`target_identity`/`snapshot_id`、凭据指代段、「同文件不收进本条」这类内部台账话。采证指针写人话文件名 |
| RF-DOC-10 | 无利用成功画面的洞（盲注/逻辑越权/配置类）= 无效果图卷：不造自绘图凑效果图；附图段仍设（前端位置图每卷必备，见 RF-IMG-03） |
| RF-DOC-11 | 危害段口径：每句「可做 X/可读 Y」要么本场实测/采证支撑，要么明标推定+未测原因；标注融入句子（「这条我实际做到了」「属于推定，未做常驻验证」），禁（实测）（推定）括号标签堆叠。出卷前必核三件：数据性质（真实业务数据 vs 演示/内存伪造，对照源码或库核实）、凭证效力（密钥实测换 token/登录/调面）、等级随实测（打脸就出修正卷，旧卷进 revisions 不改写） |
| RF-DOC-12 | 复现步骤里关键步图插在「请求包→响应包」之后（步骤文字→请求包→响应包→图）；非关键步图与汇总清单卷尾集中；图注编号「附图N」并标「步骤N」 |
| RF-DOC-13 | **回包原件保真（防手写/改写/跨场搬运回包）**：采证记录指向的每个请求/回包原件必须是本场运行态落盘，至少含一项本场可复核特征——Date 头与本场时钟一致、本机端口/socket 特征、与实测命令一致的 UA/头序；收口前主会话抽 1-2 份原件现场重放比对关键值（重放记录进验证记录段）；手写或改写回包按 H-21 伪造论处。**无视觉场机械抽验（批三十九，era≥20261016）**：`visual_available:false` 场 close 闸对 h24-replay 的 curl GET 类命令自动抽 1 条真发比对状态码——服务仍监听且回包对不上=手写实锤 fail（主会话自演抽验从唯一防线降为第二道） |

## 二、九要素顺序（RF-ELEM）

标题 → 目标网站URL → **软件与厂商信息** → 漏洞等级 → 漏洞描述 → 漏洞危害 → 涉及接口清单 → 复现步骤 → 修复建议 → ［源码依据（白盒场）］→ ［附图（本场实测截图）］→ ［验证记录（新审计场）］。

| ID | 规则 |
|---|---|
| RF-ELEM-01 | 标题一行：谁的站、做成了啥。标题/URL/等级三行连写不分＃，其余大块之间一行全角＃，禁半角 # |
| RF-ELEM-02 | 目标网站URL = 人打开的站；白盒场填项目官网，本地复现口只进复现步骤 Host，禁填本地测试地址 |
| RF-ELEM-03 | 软件与厂商信息块：①开源软件全名+版本号（与实测回包/登录页版本一致）②官方仓库 URL③该版本 release/tag/commit 链接④商用产品给厂商官网+产品页（开源：仓库+license 即厂商证明）⑤外部站/非产品站（政企门户等）写主办方全称+域名归属佐证。审核据此确认对象真实且版本没错 |
| RF-ELEM-04 | 等级只写中危/高危/严重（低危 verified 不出正式卷，levels 判 below_medium） |
| RF-ELEM-05 | 描述/危害标签单独一行，冒号后换行；**开头禁废话（2026-10-14 用户判例「dox 前面废话太多」的正文层落点）**：标题/URL/厂商/等级这些短行之后直接进描述第一段，第一段只说「什么系统、哪个功能、什么问题、造成什么后果」——禁产品百科/公司简介/漏洞分类学/审计过程叙事类铺垫，背景与细节放后面或砍；审核打开 10 秒内要知道漏洞是什么；第一人称「我」做成了啥 |
| RF-ELEM-06 | 接口清单每条带采证记录指针：「——采证记录：本场实测原件〈文件名〉」；sha256 可选——须脚本算得后贴入（同材料哈希「脚本算、人只记结果」口径），禁手编数字，无则只写文件名。**path 覆盖机械核（批四十，era≥20261016 闸核）**：清单里每个请求行 path 必须能在本场证据文本（角色目录+captures 文本件）命中——声明未实测的口直接 fail，把不同路由并成一条卷少干活在此被拦（batch31#7 升格） |
| RF-ELEM-07 | 验证记录段（新审计场）：实测日期/环境口径/行为要点。重写线场次另加「重放复测记录」+「本场实测命令原文」段（认 `v7 包 rewrite-pipeline-202610 长文（经 v7_root 解析）` §一，文件在 v7 包） |

## 三、证据图形态（RF-IMG）

| ID | 规则 |
|---|---|
| RF-IMG-01 | **效果图 = 攻击效果本体**（「别人看得懂吗」标准）：写入类 = 载荷行在列表/回包画面（新数据与装机时钟可辨）；导出类 = 导出文件内容实拍（WPS/Excel 打开，敏感列可见）；枚举/泄露类 = 回包原文全量展开分屏截全（total 与全部条目可见）。登录首页/环境全屏/「会话上下文」壳图禁充当 |
| RF-IMG-02 | **cmd 证据图 = 真终端零加工实拍**：真 cmd 交互窗口，`cls` → 单发一条命令 → 截一屏（画面只有提示符＋完整命令＋完整原始回包＋收尾提示符）；回包超一屏按 pageNum/pageSize 分多屏、每屏独立完整；禁 HTML/脚本重排「终端风格」渲染图、禁脚本二次打印替代回包原文、禁 bat 跑批冒充、禁 py/脚本控制台输出截图当命令证据；命令里内联脚本时整条命令行完整可见 |
| RF-IMG-03 | **每卷必有前端漏洞位置图**：真浏览器登录后台（择能体现漏洞位置的那侧）截漏洞所在页面，面包屑/菜单路径=位置；真实性锚点 = 浏览器渲染视口图＋面包屑＋页面数据（有地址栏更佳不强制）；纯 API 洞也截项目内最好关联的前端；项目整体无前端才用回包图顶替＋图注注明 |
| RF-IMG-04 | **越权类前端对比图**：admin 有功能入口/按钮 ↔ 低权菜单全空，真浏览器分别登录实拍，标注「UI 隐藏 ≠ 接口关闭」 |
| RF-IMG-05 | **写入/执行类 cmd 配对比组（两组缺一不可）**：①权限对照：低权同请求被拒（400/403 回包原图）vs admin 同请求成功；②落地前后（同会话同链拍摄）：攻击前基线（文件不存在 ls No such file / 表不存在 ERROR 1146 / 计数 0）＋攻击后落地（读回/marker 行/计数 N），只拍后不拍前 = 证据链断裂。泄露类：前端图自带对比即算（UI 截断指纹 vs 接口回全量），不另拍。**基线时序（2026-10-15 判例）**：基线屏必须**先于攻击动作**拍摄——攻击后补拍的「基线」拍到的是攻击后状态（表已落、计数非 0），不是基线；已落地的要回滚自建对象后整链重拍，禁止拿攻击后画面冒充基线 |
| RF-IMG-06 | **前端截图双门槛**（满足其一）：①看到漏洞效果（页面直接呈现攻击结果/泄露数据/载荷行）②多视角互补（UI vs 接口、admin vs 低权、admin 合法视图 vs 攻击所得、攻击前后）并图注点明差异。纯静态壳图（纯菜单/纯首页/无数据页）不算；例外：无变化对应图靠与同链 cmd 图配对取得证据资格 |
| RF-IMG-07 | **命令→前端效果对应图（关键步）**：关键效果步在 cmd 图外配一张「该步执行后前端变成什么样」的真浏览器视口图，图注写「执行〈命令/请求〉后，前端呈现〈什么〉」；前端无感知也截（拍受影响功能页面现状，图注如实写「前端无变化/不展示」——无感知本身是证据）；非关键步不逐命令配图；与位置图可一张两用 |
| RF-IMG-08 | **admin 合法视角对比图（所有卷标配）**：泄露类 = admin 后台正常查看该数据/配置页面 vs 攻击回包图（图注点明差异=超权多拿的部分）；篡改/写入类 = 攻击后 admin 视角看到的被改状态（证明改动真实生效）。与 RF-IMG-04/05/07 分工：04 管入口可见性、05① 管请求回包、本条管数据内容层、07 管命令→前端变化；一图多义可合并（图注写全） |
| RF-IMG-09 | **附图构成最低配比**：每卷至少 1 张「命令→前端变化对应图」（RF-IMG-07）；纯 cmd 图组合（即使 3-4 张合格实拍）不构成合格附图段；严重/复杂卷录屏必含攻击效果对应段。正向总则：**效果图必备**（有利用成功画面必交——弹窗/回显/数据落地/直链渲染/后台提权菜单等，具体形态认 RF-IMG-01）+ **佐证图按需**（战果面板/前后对照等） |
| RF-IMG-10 | **嵌图前逐张开图目验**：图注写的每个值/串/元素画面里必须有；「检查了但没看图」= 没检查 |
